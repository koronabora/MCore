# MCore

Linux-сервер для Android-клиента **MApp**. Текущая версия — проверяемая сборка 0.1.
Рабочий поиск RuTracker и Kinozal подключён через **Jackett + FlareSolverr**;
см. [настройку адаптера](docs/tracker-trial.md).

## Установленный экземпляр

- Репозиторий: `/home/kot/MCore`.
- Исполняемый код: `/opt/mcore/app`; Python venv: `/opt/mcore/venv`.
- Конфиг: `/etc/mcore/config.toml`.
- TLS-сертификат и закрытый ключ: `/etc/mcore/tls.crt`, `/etc/mcore/tls.key`.
- Пользователи, хеши ключей, история, индекс: `/var/lib/mcore/mcore.db`.
- Видео: `/var/cache/mcore/video`, по умолчанию 100 GiB.
- HTTPS API: `https://navint.space:45873` (внешний адрес).
- Торренты: `51413/TCP` и `51413/UDP`, см. [настройки сети](docs/network.md).
- TorAPI доступен только на `127.0.0.1:8443`.

Сервисы `mcore` и `mcore-torapi` запускаются при загрузке ОС и перезапускаются
после падения. Они работают от отдельного пользователя `mcore`.
Креды, база и кеш не входят в репозиторий.

## Пользователи и вход

Из root-shell:

```sh
mcore-admin create alice
mcore-admin invite alice
mcore-admin revoke alice
```

`create` создаёт пользователя; `invite` выводит одноразовую ссылку `mapp://pair?...`,
действующую **120 секунд**; `revoke` отзывает все ключи и приглашения пользователя.
Учётная запись `kot` уже создана на тестовой VM — для неё нужен только `invite kot`.
Административного HTTP API регистрации и веб-панели нет.

Приложение получает случайный 256-битный ключ доступа. В базе сохраняется только
его SHA-256; пароль пользователя не нужен. Канал шифруется стандартным TLS;
ссылка содержит отпечаток сертификата для pinning, а не закрытый ключ сервера.
Приглашение нужно передавать доверенным способом. После его погашения повторное
использование невозможно, включая параллельные запросы.

История принадлежит серверной учётной записи. Переустановка приложения и новый
вход под тем же пользователем не теряют историю. Device ID — только метка устройства.

## Развёртывание / обновление

Debian 13, от root:

```sh
apt-get install python3-venv python3-libtorrent ffmpeg nodejs npm openssl
sh /home/kot/MCore/deploy/install.sh
systemctl status mcore mcore-torapi
```

Установщик сохраняет существующие конфиг и TLS-ключ, копирует код из репозитория,
устанавливает зависимости и перезапускает службы. Изменения Python-файлов в репо
попадают в работающий экземпляр после повторного запуска установщика.
Системная версия libtorrent на VM: 2.0.11. TorAPI 0.5.2 используется с lockfile
и обновлёнными зависимостями; его HTTP-listener при установке привязывается к loopback.
Патч `deploy/patch_torapi.py` также заменяет устаревший основной адрес Kinozal
на `https://kinozal.me` для поиска, карточек, получения хеша и RSS.
Поддерживаемые источники MCore: **RuTracker и Kinozal**. `providers` может включать
оба источника или их подмножество. NNMClub и RuTor отключены. Их старые записи
скрыты из каталога и истории в API, но сохранены в базе вместе с позициями просмотра;
уже скачанные файлы и раздача кеша сохраняются. Локальное demo доступно отдельно.

При изменении пути кеша у `mcore` должны быть права на новый родительский каталог.
После перезапуска сервер копирует старый кеш в staging-каталог, переключает маркер
расположения и удаляет старую копию только после успешного копирования. Если путь
занят или копирование не удалось, используется старый кеш; причина пишется в журнал.
Нельзя вкладывать новый каталог в старый и наоборот.

Полный размер раздачи резервируется до начала скачивания её содержимого. При нехватке
места вытесняются старые завершённые раздачи, которые сейчас не читаются и не были
недавно открыты. Остальные продолжают раздаваться без ограничения по времени.
Если места всё равно нет, загрузка остаётся в ожидании с причиной в API.

Внешний адрес настроен в `public_url`. Самоподписанный TLS-сертификат покрывает
`navint.space` и локальные адреса VM; MApp доверяет ему через pin из приглашения.
После замены сертификата нужен новый вход по приглашению из-за смены pin.
Проверка внешнего HTTPS с доверием к этому сертификату и проверкой имени прошла.
Для выдачи ссылки удалённо: `ssh -p 64832 kot@navint.space`, затем `su -`
и `mcore-admin invite kot`. Проброс портов описан в `docs/network.md`.

## API

Все маршруты, кроме `POST /v1/pair`, требуют `Authorization: Bearer <key>`.

| Маршрут | Назначение |
| --- | --- |
| `POST /v1/pair` | Погашение приглашения |
| `GET /v1/home` | История и последние запросы текущего пользователя |
| `GET /v1/search?q=...&live=true` | Поиск по Kinozal, RuTracker и локальному индексу |
| `GET /v1/movies/{id}` | Объединённая карточка и обновление источников |
| `PUT /v1/history/{id}` | Позиция, торрент и файл для продолжения |
| `POST /v1/torrents` | Начало загрузки выбранной раздачи |
| `GET /v1/torrents/{id}` | Файлы, прогресс, скорость, буфер и ошибки кеша |
| `GET/HEAD /v1/torrents/{id}/files/{index}` | Видео с HTTP Range |
| `GET /v1/torrents/{id}/files/{index}/info` | ffprobe: дорожки, субтитры, длительность |
| `GET /v1/movies/{id}/poster` | Постер через сервер |
| `GET /v1/releases/{id}/screenshots/{index}` | Скриншоты выбранной раздачи |

Фоновые обновления выполняются каждые 6 часов (настраивается): RSS, поисковые
запросы, названия всех известных раздач и их подробности. Параллелизм ограничен.
Поиск поддерживает нечёткое совпадение в локальном индексе.

## Проверка

```sh
cd /home/kot/MCore
/opt/mcore/venv/bin/python -m pytest -q
```

Проверяются одноразовость приглашения при гонке, истечение срока, изоляция истории,
возврат истории после нового входа, TCP/UDP-bind libtorrent, перенос кеша, защита
прокси изображений от внутренних адресов, настоящий локальный торрент и HTTP Range.
Торрент-тест также проверяет, что содержимое не скачивается до выделения места в кеше.

`tests/local_demo.py` создаёт синтетический 30-секундный ролик ffmpeg для локального
тестирования Android. Он установлен в каталог как **MCore demo**. `tests/live_smoke.py`
проверяет установленный HTTPS API, аудиометаданные, скриншот и SHA-256 видео.
`tests/check_restart.py` — root-only проверка восстановления службы после SIGKILL.

## Границы текущей версии

Связка **Jackett + FlareSolverr** авторизована и подключена к MCore.
Проверено: 62 видеораздачи по запросу «Интерстеллар» от обоих источников,
получение torrent/magnet и 38 серверных тестов. Полная загрузка реального фильма
в этой проверке не выполнялась. Инструкции: [интеграция](docs/tracker-trial.md).

- DNS на VM настроен на `8.8.8.8`. До подключения FlareSolverr проверка 2026-11-01 показала:
  главные страницы RuTracker и Kinozal отвечают HTTP 200, поиск обоих источников
  отвечает HTTP 403 с `cf-mitigated: challenge` (проверка Cloudflare).
  Это подтверждено для `rutracker.org`, `rutracker.net`, `kinozal.me`, `kinozal.guru`;
  `rutracker.nl` не завершил TLS-handshake за время проверки. Запросы с браузерным
  TLS-профилем Chrome и предварительным открытием главной также получили challenge.
  TorAPI скрывает эту причину за общим `Server is not available`.
  В upstream TorAPI встроены cookies аккаунтов; вместо них теперь используются
  собственные серверные сессии Jackett вне репозитория и FlareSolverr.
- TorAPI не отдаёт полный исторический каталог всех трекеров. Фоновый индекс строится
  из RSS и найденных раздач, а не представляет собой зеркало всех их страниц.
- Объединение карточек пока эвристическое: нормализованное название + год.
  Нужна дальнейшая проверка неоднозначных названий, ремейков и разных переводов.
- Постеры, режиссёры и описания зависят от данных источника. Скриншоты берутся из
  источника, если он их предоставляет, либо генерируются из полностью кешированного видео.
- Буфер оценивается консервативно по объёму данных; настройка в секундах пока не
  является точным расчётом по битрейту конкретного файла.
- Интернет-проверка проброса ещё не выполнялась. Пользователь подтвердил работу
  предложенных локальных сценариев на телефоне; модель и версия Android не указаны.

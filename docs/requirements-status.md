# Выполнение исходного ТЗ

Сверка по исходному тексту пользователя; MCore 0.3.4 и MApp 0.3.4.

## Обновление 0.3.4

Добавлены постоянные манифесты источников, очередь индексации метаданных и выдача
произведений с доступными источниками (`works`, `/v1/movies/{id}/sources`).
Индексация не резервирует видеокеш и не запускает загрузку содержимого. Данные IMDb
импортируются по явным ID, включая ID эпизодов и состав сезонов; неопределённые файлы
не объединяются по похожему имени. Полнота сезона подтверждается отдельно.

Выдача видео читает торрент-части через дисковый слой libtorrent и дополнительно
проверяет SHA-1 частей v1. Клиентские проверки SHA-256 блоков сохранены.
Маленькие/широкие изображения постеров отклоняются на сервере и клиенте.
Манифесты сохраняются при вытеснении видеоданных; восстановленные раздачи защищены
от немедленного вытеснения после перезапуска.

На физическом телефоне полный скачанный AVI совпал по SHA-256 с серверным.
Артефакты воспроизведены в системном MPEG-4 MediaCodec и отсутствовали в снятых
кадрах при программном декодировании VLC. MApp автоматически использует этот обход
для Xvid/DivX, также предусмотрен ручной выбор декодера.

Клиент 0.3.4 использует две постоянные кнопки, локальные данные после начала скачивания,
настраиваемый порог просмотра 10%, остановку без удаления и сохранение внешнего плеера.
Подробнее: MApp/docs/release-034.md. Исторические разделы ниже описывают предыдущие выпуски.
Оговорки ниже обозначают ограничения данных источников и измерений.
Данные доступа к VM сюда не включены.

## Последующие согласованные изменения

- Названия проектов: MCore и MApp; уникальность торговых названий не проверялась.
- Источники: только Kinozal и RuTracker.
- Встроенный LibVLC по умолчанию, внешний плеер — настройка.
- Оранжевая собственная иконка камеры, настраиваемые цвета интерфейса.
- История привязана к серверному аккаунту. Android ID — метка устройства,
  не средство восстановления ключа после удаления приложения. Повторный вход
  в тот же аккаунт возвращает историю.
- API уже проверен через внешний адрес; текущие параметры доступа к VM отличаются
  от первоначальных. Torrent TCP/UDP и административный SSH существуют отдельно.

| Только API доступен клиенту | Готово | Все медиа, поиск, изображения и загрузки через MCore; torrent-сеть требует отдельных исходящих соединений и имеет отдельный настраиваемый входящий порт |
| Трекеры доступны только с сервера | Готово | Jackett + FlareSolverr; два согласованных источника |

| Текущие сиды/пиры при открытии карточки | 0.2.1 | Ожидание обновления поиска до 20 с на источник; недоступные/невернувшиеся записи явно помечены как устаревшие |
| Скачивание на телефон только с сервера | Готово | HTTPS Range, проверка SHA-256 каждой части |

## Интегрированная проверка 0.3.0

50 серверных тестов; сборка и lint Android; все шесть instrumentation-сценариев.
На установленном сервере проверены неполный AVI (метаданные, кадр, начальный/
средний/конечный буфер), MKV/MP4 с субтитрами и разные исторические страницы
обоих трекеров. На эмуляторе — выбор серий, независимая история и воспроизведение.
Полный архив ещё наполняется; данные, отсутствующие у источников, не выдумываются.

## Обратная связь 0.3.1

Исправлены пробелы RuTracker и дубли двух документальных сериалов из отчёта;
добавлены компактные плашки с серым режиссёром, полноэкранные скриншоты с масштабом,
разделение истории запросов/переходов, главная «Кинозал» и кнопка-лупа.
Перед запуском виден процент подготовки; файл без метаданных не объявляется готовым.
Настройка логирования сохраняет диагностический файл в папку видео и удаляет его
при выключении. Ключи и приглашения в лог не попадают.

## Обратная связь 0.3.2

Оформление главной/настроек/поиска уточнено; кнопка и системный возврат из карточки
восстанавливают экран поиска вместе с запросом, результатами и прокруткой.
Добавлено совпадение всех слов независимо от дефисов и регистра, сохранён RapidFuzz.
В живом индексе «Человек паук» возвращает продолжения и составные названия.
Ошибка 409 из пользовательского лога воспроизведена для RuTracker и устранена
через получение доступной magnet-ссылки страницы. Подготовка раздачи не дублируется.
С открытым портом проверены получение данных Kinozal и SHA-256 первого МиБ через API.

Финальные проверки 0.3.2: 58 серверных тестов; Android release/test сборки и lint;
восемь режимов инструментальных проверок (navigation, feedback, основной,
player, audio, library, card, episodes). В navigation проверены системный возврат
и кнопка «Назад». Синтетические фильмы восстановлены перед проверками библиотеки
и серий; интерфейс главной, поиска и настроек также проверен по снимкам экрана.

## Обратная связь MApp 0.3.3

Выбор общей папки предложен при первом запуске, с начальным переходом на доступную
съёмную карту. Сезоны/серии выбираются раздельно; скачивание сезона и всех сезонов
проверено на частной раздаче из двух сезонов и трёх файлов, без дублей в очереди.
Скачанные серии имеют отдельные плашки и кнопки удаления фиксированного размера.
Из карточки сохранённый файл открывается непосредственно.

Внешнее воспроизведение использует foreground HTTP bridge с чтением проверенных
локальных байтов и дозагрузкой через pinned HTTPS. Проверены неполный AVI во внешнем
VLC, возврат позиции и сохранение карточки. Встроенные прозрачные элементы управления
заменили нижнюю непрозрачную панель. Проверены пересоздание карточки Android, независимые
позиции серий и отсутствие потери позиции при параллельном скачивании.
Лог MApp-debug2.txt фиксирует пересоздание MainActivity после внешнего просмотра,
но не содержит нативного отчёта о падении VLC. Нельзя утверждать, что все внешние
падения имели одну причину. Плеер без возврата результата не передаёт точную позицию.

Android: сборки release/androidTest и lint; 11 режимов проверок. Код серверного API
в этом выпуске не изменялся; добавлен только приватный тестовый multiseason_demo.py.

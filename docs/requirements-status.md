# Выполнение исходного ТЗ

Сверка по исходному тексту пользователя и коду после 0.2.0. Следующий выпуск —
0.2.1. «Частично» означает оставшуюся работу, даже если основной сценарий работает.
Данные доступа к VM сюда не включены.

## Последующие согласованные изменения

- Названия проектов: MCore и MApp; уникальность торговых названий не проверялась.
- Источники: только Kinozal и RuTracker.
- Встроенный LibVLC по умолчанию, внешний плеер — настройка.
- Оранжевая собственная иконка камеры, настраиваемые цвета интерфейса.
- История привязана к серверному аккаунту. Android ID — метка устройства,
  не средство восстановления ключа после удаления приложения. Повторный вход
  в тот же аккаунт возвращает историю.
- API уже проверен через внешний адрес; текущие параметры доступа к VM отличаются
  от первоначальных. Torrent TCP/UDP и административный SSH существуют отдельно.

## Сервер

| Требование | Статус | Реализация / оставшаяся работа |
| --- | --- | --- |
| Linux, Debian 13, нормальная torrent-библиотека | Готово | Python, libtorrent 2, systemd |
| Шифрованный API, порт >40000, конфиг | Готово | HTTPS с pinning, 45873, TOML |
| Создание пользователей внутренним скриптом | Готово | mcore-admin, веб-регистрации нет |
| Логин и ключ вместо пароля, защита данных | Готово | Именной аккаунт, случайный bearer-ключ; хеш на сервере, Android Keystore на клиенте; это не протокол WireGuard |
| Временная ссылка, 2 минуты | Готово | Одноразовое приглашение с сервером и TLS-pin |
| Только API доступен клиенту | Готово | Все медиа, поиск, изображения и загрузки через MCore; torrent-сеть требует отдельных исходящих соединений и имеет отдельный настраиваемый входящий порт |
| Трекеры доступны только с сервера | Готово | Jackett + FlareSolverr; два согласованных источника |
| Дисковый кеш, размер/путь, перенос | Готово | Резервирование места, staging-перенос, сохранение старого при ошибке |
| Долгое сидирование, восстановление после падения | Готово | Resume-данные, вытеснение неактивного завершённого кеша, systemd |
| Фоновая синхронизация каждые 6 часов | Частично | Интервал настраивается; обновляются свежая выдача, запросы и известные раздачи. Полный обход всех исторических раздач не реализован |
| Текущие сиды/пиры при открытии карточки | 0.2.1 | Ожидание обновления поиска до 20 с на источник; недоступные/невернувшиеся записи явно помечены как устаревшие |
| Скачивание на телефон только с сервера | Готово | HTTPS Range, проверка SHA-256 каждой части |

## Следующие этапы после 0.2.1

1. Метаданные недокачанного видео: длительность, битрейт, аудио/субтитры;
   буфер по реальному времени и позиции продолжения.
2. Единая модель сезонов/эпизодов и история по эпизодам.
3. Надёжнее объединять альтернативные названия и заполнять карточки поиска.
4. Расширить синхронизацию: сохраняемый курсор, прогресс, повтор ошибок;
   отдельно проверить возможность исторического обхода каждого из двух трекеров.

Полное исходное ТЗ не объявляется завершённым выпуском 0.2.1.

# MCore 0.4.2

Потоковый просмотр: `buffer` по умолчанию 180 секунд (до 900), `percent`
по умолчанию 10 (1–100). Для выбранного файла/позиции проверяются все части
большего из двух объёмов: процент файла или время по средней скорости с
25% запасом. Объём ограничен остатком файла. Дополнительно обязательны
заголовок, хвост контейнера и полученная ffprobe длительность (`index_ready`).
Это проверка реально имеющихся частей, а не искусственная задержка старта:
готовый кеш позволяет начать сразу. Подготовка скриншотов сохраняет прежний
небольшой объём запроса и не включает новый пользовательский порог.

Финальный общий прогон: 100 тестов прошли. Старый тест индекса теперь явно
задаёт 15 секунд, чтобы отдельно проверять окно контейнера. Новые тесты
проверяют процент, минуты, отсутствие индекса/длительности и конец файла.

Раздача со скриншота 0.4: `kinozal:1803576`, «Во все тяжкие», 13.72 GiB,
`d2f0f5b335bbda0d17087d684774865b316058aa`, имя торрента `Season_01`.
При диагностике она была metadata-only, 0 байт, и скрывалась стандартной
панелью mcore-top. Причина незапущенной очереди в 0.4 исправлена в MApp 0.4.1.

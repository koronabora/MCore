# Порты MCore

| Назначение | Значение по умолчанию | Проброс / входящий firewall |
| --- | --- | --- |
| HTTPS API для MApp | `45873/TCP` | Разрешить клиентам |
| BitTorrent peer connections | `51413/TCP` | Разрешить из интернета |
| BitTorrent uTP и DHT | `51413/UDP` | Разрешить из интернета |
| Внутренний TorAPI | `127.0.0.1:8443/TCP` | Не пробрасывать |

За NAT пробросить `51413/TCP` и `51413/UDP` на те же порты IP сервера.
API и BitTorrent настраиваются независимо в `/etc/mcore/config.toml`.
Для IPv6 добавить `"::"` в `torrent.listen_addresses` и разрешить порты
в IPv6 firewall. NAT-проброс для IPv6 обычно не нужен.

В секции `[torrent]` задаются порт и адреса прослушивания, DHT, PEX,
uTP, поиск локальных пиров (LSD), UPnP/NAT-PMP, лимит соединений и скорости
в байтах/секунду. Ноль для скорости означает отсутствие лимита.
TCP включён всегда; UDP-порт используется libtorrent для DHT/uTP.
Приватность раздач учитывает libtorrent: приватные торренты не используют DHT/PEX.

UPnP/NAT-PMP по умолчанию выключены: проброс выполняется вручную.
При включении LSD библиотека использует локальный multicast `239.192.152.143:6771/UDP`
(и IPv6 multicast при его поддержке); этот порт не нужно пробрасывать из интернета.

Исходящие подключения к пирам, трекерам, DNS и сайтам должны быть разрешены;
ответы — разрешены stateful-правилом `established,related`.
`outgoing_port_first`/`outgoing_port_last` ограничивают только исходные порты
исходящих TCP-подключений к пирам. По умолчанию `0/0`: их выбирает ОС.
Это не порты назначения и не диапазон входящего проброса.

После изменения конфига перезапустить `mcore.service`. Занятый торрент-порт
не заменяется случайным: запуск должен завершиться с ошибкой в журнале.
SSH остаётся административным доступом и не используется приложением.

Проверка после запуска:

```sh
ss -lntup
journalctl -u mcore -n 50 --no-pager
```

Открытый порт помогает доступности пиров, но скорость также зависит от сидов,
канала и диска. Проверка проброса из интернета проводится отдельно от локальных тестов.
